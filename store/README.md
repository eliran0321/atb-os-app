# דף האפליקציה בחנות של אפל

הכול כאן ממלא את הטיוטה ב-App Store Connect. רק `submit.mjs --go` שולח לבדיקה של אפל.

- `he.mjs` - הטקסטים (כותרת משנה, תיאור, מילות מפתח, כתובות), הקטגוריות,
  המדינות, וההערות לבודק באנגלית. משנים כאן ומריצים שוב את `listing.mjs`.
- `listing.mjs` - כותב את הטקסטים, הקטגוריות, דירוג הגיל (4+), זכויות התוכן,
  הבנייה התקינה האחרונה, מחיר חינם, זמינות והערות לבודק. `node store/listing.mjs`
- `shots.mjs` - מפיק את צילומי המסך: המסך האמיתי של המערכת עם נתוני הדוגמה שלה,
  בתוך מסגרת של מכשיר עם כיתוב (`frame.mjs`). חמישה לאייפון (1290x2796) וחמישה
  לאייפד (2048x2732). צריך את התיקייה של ATB-OS ליד הריפו הזה (או `ATB_OS_DIR`)
  ואת שרת הפיתוח שלה על 3030. `node store/shots.mjs <תיקייה>`
- `upload-shots.mjs` - מעלה את הצילומים ומחליף את הקיימים.
  `node store/upload-shots.mjs <תיקייה>`
- `submit.mjs` - בודק שהכול מוכן להגשה, ועם `--go` מצרף את הבנייה התקינה האחרונה
  ומגיש. בודק שהגרסה בהכנה, שיש בנייה תקינה, ושהקוד של חשבון ההדגמה שנשמר אצל
  אפל הוא הקוד שהמערכת מצפה לו (הגישה לבודקי החנויות פתוחה ורחוקה מהתפוגה). את
  הקוד בעל החשבון מדביק בעצמו ב-App Store Connect; הסקריפט לא מדפיס אותו ולא כותב
  אותו. צריך את התיקייה של ATB-OS, כמו הצילומים.
  `node store/submit.mjs --min-build <מספר> [--go]`

הצילומים עצמם לא בריפו: הם אצל אפל, והמחולל מפיק אותם מחדש.

מה לא נעשה מכאן, כי אין לזה API או כי זה של בעל החשבון: פרטי הקשר והקוד של
חשבון ההדגמה לבודק, ושאלון הפרטיות (App Privacy).
